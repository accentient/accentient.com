<p>Wow, two great speakers in less than a month. Last month, we had <a href="https://accentient.com/blog/KalenDelaneyInBoiseTonight.aspx" target="_blank" rel="noopener">Kalen Delaney speaking at Boise's inaugural SQL Server User Group</a> and tonight at the <a href="http://www.netdug.com" target="_blank" rel="noopener">Idaho .NET User Group</a>, <a href="http://msmvps.com/blogs/kathleen" target="_blank" rel="noopener">Kathleen Dollard</a> an <a href="http://www.ineta.org" target="_blank" rel="noopener">INETA</a> speaker is sharing her "<a href="http://www.netdug.com/default.aspx?CntProv=Events&amp;CntItem=4373fc4b-d222-4d38-9f4d-69553c5fa643" target="_blank" rel="noopener">Twelve Gems and Eight Dragons talk.</a>"</p> <p><img style="border-right: 0px; border-top: 0px; border-left: 0px; border-bottom: 0px" height="295" alt="dollard" src="dollard.jpg" width="226" border="0"> </p> <p><u>Here are the Twelve Gems</u></p> <ul> <li><a href="http://blogs.msdn.com/clraddins" target="_blank" rel="noopener">System.AddIn</a> - one of two new features in 3.5 that are getting overlooked; allows you to let other people provide customization to your application; wraps everything about managing app domains; check out the <a href="http://www.codeplex.com/clraddins" target="_blank" rel="noopener">Pipeline Builder tool</a> on CodePlex</li> <li><a href="http://msdn.microsoft.com/en-us/library/bb359438.aspx" target="_blank" rel="noopener">HashSet</a> - sets = groups and very high performance, and sets are mutable; LINQ allows set-type functions, but is missing some features and always returns copies</li> <li><u>WPF Async Data Loading</u> - Asynchronous behavior offered for instance loading and (sometimes) property retrieval, by leveraging the <a href="http://msdn.microsoft.com/en-us/library/system.windows.data.objectdataprovider.isasynchronous.aspx" target="_blank" rel="noopener">ObjectDataProvider IsAsynchronous property</a> in XAML</li> <li><a href="http://msdn.microsoft.com/en-us/library/sz6zd40f.aspx" target="_blank" rel="noopener">Generic Classes C#</a> - Generic classes encapsulate operations that are not specific to a particular data type; the most common use for generic classes is with collections like linked lists, hash tables, stacks, queues, trees, and so on. Operations such as adding and removing items from the collection are performed in basically the same way regardless of the type of data being stored; Why generics? improve performance, enhanced behavior with 3.5, improve robustness by catching typing errors at compile time, reduce amount of code via generic refactoring; Kathleen's guidance is to stop using <a href="http://msdn.microsoft.com/en-us/library/system.collections.aspx" target="_blank" rel="noopener">System.Collections</a> and replace it with <a href="http://msdn.microsoft.com/en-us/library/system.collections.generic.aspx" target="_blank" rel="noopener">System.Collections.Generic</a></li> <li><a href="http://msdn.microsoft.com/en-us/library/6kxxabwd.aspx" target="_blank" rel="noopener">Refactor/Rename</a> - in her opinion the most commonly used refactoring; <a href="http://msdn.microsoft.com/en-us/library/ckfya594.aspx" target="_blank" rel="noopener">now available in Visual Basic as well</a></li> <li><u>Snippets (your own)</u> - Microsoft's provided snippets are marginal; Kathleen says not to use <a href="http://msdn.microsoft.com/en-us/vbasic/bb973770.aspx" target="_blank" rel="noopener">Microsoft's snippet editor</a>, but rather <a href="http://billmccarthy.com/Projects/Snippet_Editor/" target="_blank" rel="noopener">Bill McCarthy's Snippet Editor 2008</a> instead</li> <li><u>Understanding Your Code</u> - static analysis (<a href="http://msdn.microsoft.com/en-us/library/bb429476(vs.80).aspx" target="_blank" rel="noopener">FxCop</a>, VSTS Code Analysis - but custom rules are hard), code-based analysis (<a href="http://submain.com/?nav=products.cir" target="_blank" rel="noopener">CodeIt.Right</a> and <a href="http://code.msdn.microsoft.com/sourceanalysis" target="_blank" rel="noopener">StyleCop</a>), and <a href="http://msdn.microsoft.com/en-us/library/bb385914.aspx" target="_blank" rel="noopener">VSTS Code Metrics</a> (maintainability index, cyclomatic complexity, depth of inheritance, class coupling, and lines of code) - cool and (some parts) are useful, unit test code coverage, and performance</li> <li><a href="http://msdn.microsoft.com/en-us/library/ms182519.aspx" target="_blank" rel="noopener">Data Driven Unit Testing</a> - data sources define conditions, can be Excel, quality team can be included and expand the list, consider naming classes by condition, do not demand 1:1 class correspondence, and anticipate n:1 test correspondence</li> <li><a href="http://msdn.microsoft.com/en-us/library/bb383977.aspx" target="_blank" rel="noopener">Extension Methods</a> - Extension methods enable you to "add" methods to existing types without creating a new derived type, recompiling, or otherwise modifying the original type so you don't have to wait for Microsoft to provide functionality you'2013-08-28 18:17:51've been waiting for; </li> <li><a href="http://msdn.microsoft.com/en-us/library/system.exception.data.aspx" target="_blank" rel="noopener">System.Exception.Data</a> - a key/value pair collection to provide additional, user-defined information about the exception</li> <li><a href="http://msdn.microsoft.com/en-us/library/wa80x488.aspx" target="_blank" rel="noopener">Partial Methods</a> - separate responsibility, pretty useless unless they can interact; partial methods allow interaction between partial classes; they required definition of clear extensibility points and are a replacement for intra-object dependency</li> <li><a href="http://msdn.microsoft.com/en-us/library/46xf4h0w.aspx" target="_blank" rel="noopener">Document Outline</a> - provides an outline view of elements and scripts in the current document (Web or Windows forms)</li></ul> <p><u>Here are the Eight Dragons</u></p> <ul> <li><a href="http://msdn.microsoft.com/en-us/library/2cf62fcy.aspx" target="_blank" rel="noopener">VB vs. C# nullable operators</a> - be careful here because a lot of combinations of =, &lt;, &gt;, etc. may give unexpected results </li> <li>Inheriting from Collections. Generic.List - Microsoft decided List should have max performance so they sealed everything to avoid virtual table calls, so you can't modify, add events, anything; </li> <li>Interface versioning - everything implementing the interface is broken, so create a new interface or consider using a base class</li> <li>Immutability in anonymous types - once you place something in a dictionary, its hash must not change; anonymous types are used most in LINQ; in C#, all instances of anonymous types are immutable, but VB uses a key to define a immutable fields of anonymous types and if the key is missing, it will use reference semantics so for LINQ consistency, uses full value semantics in LINQ</li> <li>The New constraint - the most useless piece of junk related to generics; generics provide 3 constraints: base, interface, and new; the "New" constraint requires public parameterless constructor and this is not consistent with most good development; instead you should use reflection to instantiate</li> <li>Unexpected LINQ evaluation</li></ul> <p><u>Landscape Complexity</u></p> <ul> <li>if we are feeling overwhelmed (and we should be given the complexity of .NET 3.5) with so many languages, data bases, server solutions, data access, presentation</li> <li>There is a frightening pace of change, which is a generally a good thing, but we are losing hobbyists, one man shops</li> <li>No one is competent anymore</li> <li>You cannot know it all</li> <li>Code for change - assemblies (n-tier and beyond, wrap XML, wrap communication, wrap office automation, wrap special library access) , class design (interface coding, partial classes, generics), code design (lambdas, LINQ core), big picture (source control, CI, reluctant polyglot programming, code generation, testing, metadata - DRY4D - don't repeat yourself in the 4th dimension (time)</li></ul> <p><u>Other terms overheard this evening</u></p> <ul> <li><a href="http://en.wikipedia.org/wiki/Polyglot_(computing)" target="_blank" rel="noopener">Polyglot Programming</a> - using the best language for the job; in this case, C# or VB :-)</li> <li>CTRL + Shift + V - Cycle through the clipboard in Visual Studio</li> <li>CTRL + A + C - Copy the text out of a dialog window</li>
</ul>
