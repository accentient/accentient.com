<b>Bottom line up front:&nbsp; Create a 'root' branch directly under the source control branch associated with a new Team Project.</b><br /><br />I see this all the time...&nbsp; Someone creates a new source control branch in TFS and starts creating solutions underneath the default project branch.&nbsp; In other words, they end up with this:<br /><br />$/ProjectName<br />&nbsp;&nbsp;&nbsp; /SolutionName1<br />&nbsp;&nbsp;&nbsp; &nbsp;&nbsp;&nbsp; /ProjectName1<br />&nbsp;&nbsp;&nbsp; &nbsp;&nbsp;&nbsp; /ProjectName2<br />&nbsp;&nbsp;&nbsp; /SolutionName2<br />&nbsp;&nbsp;&nbsp; &nbsp;&nbsp;&nbsp; /ProjectName3<br />&nbsp;&nbsp;&nbsp; &nbsp;&nbsp;&nbsp; /ProjectName4<br /><br />Now, the difficult comes when the shop needs to create a second version of the application.&nbsp; Code branches directly under the root (i.e., $/ProjectName) can only be created when a new Team Project is created.&nbsp; If, in the above example, SolutionName1 and SolutionName2 both belong to the current version of the application, then creating a new version of the application will require either the creation of a new team project (with a branch from the $/ProjectName), or a wildly unweildly structure where each solution is branched, resulting in something like:<br /><br />$/ProjectName<br />&nbsp;&nbsp;&nbsp; /SolutionName1<br />&nbsp;&nbsp;&nbsp; &nbsp;&nbsp;&nbsp; /ProjectName1<br />&nbsp;&nbsp;&nbsp; &nbsp;&nbsp;&nbsp; /ProjectName2<br />&nbsp;&nbsp;&nbsp; /SolutionName2<br />&nbsp;&nbsp;&nbsp; &nbsp;&nbsp;&nbsp; /ProjectName3<br />&nbsp;&nbsp;&nbsp; &nbsp;&nbsp;&nbsp; /ProjectName4<br />&nbsp;&nbsp;&nbsp; /SolutionName1_v2<br />&nbsp;&nbsp;&nbsp; &nbsp;&nbsp;&nbsp; /ProjectName1<br />&nbsp;&nbsp;&nbsp; &nbsp;&nbsp;&nbsp; /ProjectName2<br />&nbsp;&nbsp;&nbsp; /SolutionName2_v2<br />&nbsp;&nbsp;&nbsp; &nbsp;&nbsp;&nbsp; /ProjectName3<br />&nbsp;&nbsp;&nbsp; &nbsp;&nbsp;&nbsp; /ProjectName4<br /><br />A MUCH cleaner approach is so simple, yet requires a bit of forethought.&nbsp;
