<p>I found a few more answers to some questions that came up during the ISV Community Days Tour.<br /><br /><strong>Q.</strong> Will there be an XML data type in SQL Mobile?<br /><strong>A.</strong> No. In Beta 2 there is not an XML data type. If you replicate a SQL Server table with a XML datatype it converts it to ntext in the SQL Mobile database. You can see more information at the end of <a href="http://msdn.microsoft.com/library/default.asp?url=/library/en-us/dnsql90/html/sql2k5xmloptions.asp" target="none" rel="noopener">this article</a>.<br /><br /><strong>Q.</strong> Can you index a managed UDT column? If so, does it index on what the implemented ToString() provides?<br /><strong>A.</strong> Yes; we can define constraints on UDTs (PKs, FKs): constraints are implemented with indexes; the &#8220;key&#8221; is created with the serialized value; when you create the UDT, you must define how the value is going to be serialized: <em>Format.Native or Format.UserDefined. </em>If you select <em>UserDefined</em> format, you must implement the Sql.IBinarySerialize interface coding the methods Read and Write to serializate and deserializate the value. You can create an index on the column, as long as SQL knows which value to index, and this is what you decide when you select how to serialize the UDT.<br /><br /><strong>Q.</strong> I&#8217;ve heard that <em>Intellisense</em> is gone, will we see it back in any form? Maybe for just T-SQL or&nbsp;system sprocs?<br /><strong>A.</strong> It was dropped when Beta2 came; I think we will not have it in any form.<br /><br /><strong>Q.</strong> I&#8217;ve been hearing scary things about the scalability of managed UDTs &#8211; anything public on this yet? Some students are thinking that since Microsoft dropped <em>ObjectSpaces</em>, this is an alternative.<br /><strong>A</strong>. We must think about UDT as an extension of scalar types (date, time, points and so); we should not think of UDT as extension of business objects (Employee, Address, Contact,&#8230;). For this release, CLR UDTs are meant to be a mechanism to create new scalar data types, not complex objects, so it is NOT a replacement for ObjectSpaces. Balaji published a <a href="http://msdn.microsoft.com/sql/default.aspx?pull=/library/en-us/dnsql90/html/sqlclrguidance.asp" target="none" rel="noopener">white paper</a> which talks about this.<br /><br /></p>
