<p>At <a href="http://europe.msteched.com/" target="_blank" rel="noopener">TechEd Europe 2010</a>, I had the privilege to work on the VS2010 Ultimate booth. It was great to meet so many folk, and find out how different people were using TFS and VS2010.</p> <p>One recurring question was about upgrading, and the ways to do it.</p> <p>Neno Loje delivered a great talk about administration of TFS, in which he covered a range of topics, including upgrading. I recommend watching the recording to check how you are doing. The recording is at&nbsp; <a title="http://www.msteched.com/2009/Europe/DEV311" href="http://www.msteched.com/2009/Europe/DEV311">http://www.msteched.com/2009/Europe/DEV311</a>. <p>&nbsp; <p>He recommended an approach that will import the previous version in to a new instance of TFS. The advantages of this is that you can move to a 64 bit application tier, and have the certainty that the new instance is up and running before importing the existing data.  <h3>Recommended Reading</h3> <p>The devil is in the detail, and it is well worth reading up on the upgrade process:  <p>&nbsp;</p> <table border="0" bordercolor="#0000a0" cellpadding="2" width="90%" bgcolor="white" align="center"> <tbody> <tr> <td><strong>Topic</strong></td> <td><strong>Link</strong></td></tr> <tr> <td>The TFS upgrade guide</td> <td><a href="http://vs2010upgradeguide.codeplex.com/">http://vs2010upgradeguide.codeplex.com/</a></td></tr> <tr> <td>Upgrade options</td> <td><a href="http://blogs.msdn.com/b/bkrieger/archive/2009/10/21/team-foundation-server-2010-upgrade.aspx">http://blogs.msdn.com/b/bkrieger/archive/2009/10/21/team-foundation-server-2010-upgrade.aspx</a></td></tr> <tr> <td>How to Upgrade</td> <td><a href="http://blogs.msdn.com/b/bharry/archive/2009/10/21/upgrading-from-tfs-2005-2008-to-tfs-2010.aspx">http://blogs.msdn.com/b/bharry/archive/2009/10/21/upgrading-from-tfs-2005-2008-to-tfs-2010.aspx</a></td></tr> <tr> <td>TFS Config command overview</td> <td><a href="http://msdn.microsoft.com/en-us/library/ms253116(VS.100).aspx">http://msdn.microsoft.com/en-us/library/ms253116(VS.100).aspx</a> </td></tr> <tr> <td>TFS Config Import command details</td> <td><a href="http://msdn.microsoft.com/en-us/library/ff407080.aspx">http://msdn.microsoft.com/en-us/library/ff407080.aspx</a></td></tr></tbody></table> <p>&nbsp; <h3>Step Summary</h3> <ol> <li>Create the new instance of TFS with all the correct configuration, preferably on 64 bit Application Tier connecting through to the database.  <li>Then configure and test the new instance to ensure that you can see the work items, reports etc.  <li>Then copy a backed up version of your databases over to the new sql server  <li>Then import the old databases using the command line (you need to open a command prompt as an administrator, and navigate to the tfstools folder), this example was taken from the Brian Harry Blog Link.</li></ol> <p><font color="#0000ff" size="2" face="Consolas">Tfsconfig import /connectionString:"Data Source=DT01;Initial Catalog=TfsIntegration;Integrated Security=SSPI" /collectionName:UpgradedCollection /sqlinstance:&lt;SQL Instance Name&gt;</font>  <p>&nbsp; <p>This will import the existing TFS data in to a new project collection, and there may be some massaging required to correct any project template customisations, as well as reports.  <p>&nbsp; <p>&nbsp; <p>Remember to try this in a test environment first, to ensure that the process is known before completing the production run.</p>
