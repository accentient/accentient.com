<p>The MOC 2631 Beta is over.&nbsp; Whew!&nbsp; What an experience!&nbsp; Lots of excellent lessons learned.&nbsp; </p>
<ol>
<li>Boeing and Safeco (our guinea pig companies) have some great employees!&nbsp; Some good developers, architects, testers and project managers.&nbsp;
<li>Many of the students really GOT Team System.&nbsp; They saw how it could work in the team.&nbsp; But almost everyone wanted to see more.&nbsp; Both deeper content in their roles, and also more about how the other roles were using Team System.
<li>Beta attendees had some really strong feelings on how VSTS should be taught.&nbsp; There are two schools of thought (roughly): Some attendees wanted to work with all of the roles, so they wanted to&nbsp;walk though an entire&nbsp;dev project acting as each role in turn.&nbsp;&nbsp;Others wanted to stay in a&nbsp;single role, and&nbsp;work as part of an overall team.&nbsp; This course was designed for the second group of folks, since&nbsp;we work with a&nbsp;team with many roles, each one working&nbsp;as part of the dev lifecycle, until a final&nbsp;project is built and deployed.&nbsp;
<li>People are VERY patient with Beta software and beta courseware.&nbsp; We had several problems, some of&nbsp;our causing (the courseware) and some&nbsp;not.&nbsp;&nbsp;Everyone was very patient,&nbsp;very helpful, and&nbsp;full of good suggestions.&nbsp; My faith in humanity is restored!
<li>Microsoft needs to spend some serious time explaining the difference between a MOC course and a MOC workshop.&nbsp; In a course, the instructor&nbsp;<strong>teaches</strong>&nbsp;about 50% of the time, and labs reinforce the learning.&nbsp; In a workshop, there is very little <strong>teaching</strong>.&nbsp; Only the bare minimum is explained and&nbsp;attendees are expected to learn through self-discovery.&nbsp; This&nbsp;throws people, both attendees and instructors, to no end.&nbsp;&nbsp;Very few people&nbsp;'get' it before having lived it at&nbsp;least once.&nbsp; Most hard-core&nbsp;folks love it after a couple days, but some people prefer&nbsp;passive learning.&nbsp; It's tough to&nbsp;build a course for&nbsp;everyone, and workshops are an extreme example of this.
<li>Unless you're doing a demo, try not to run TFS inside a VPC.&nbsp; It has issues.&nbsp; Our TFS had trouble holding up to the 11 student load and crashed at least once a day when load was high.&nbsp; (It appears that having more than one or two people creating projects at the same time was enough to bring it down.)&nbsp; Now, don't get panicked.&nbsp;&nbsp;We were running in a VPC.&nbsp; Specifics: Host was a 2.8 GHz processor with 3 Gig of RAM.&nbsp; We gave the VPC client 2.3 Gig of RAM.&nbsp; We thought that might be enough to host 11 heavy users, but it couldn't quite hold up.&nbsp; Now, MS dogfoods Team System with thousands of users, so I'2013-08-28 13:50:17'm confident this is a configuration or VPC issue.&nbsp; Still, we've followed all the set-up guides and tips and tricks we could find.&nbsp; (And, yes, if we put VS2005 directly on the image and run it as an all-in-one VPC, everything works fine...&nbsp; with a load of 1 person...)
<li>Still several user interface bugs in VS2005.&nbsp; We've run into a reproducible error that drives us batty.&nbsp; We have a web service project open that was checked out from source control.&nbsp; We create a test by right clicking a method in the Web service.&nbsp; Test creation fails.&nbsp; If we close VS2005, and reopen it and reload the project (with the project already checked out from source control), it will create the test just fine.&nbsp; This is just one of them.&nbsp; We've run into lots!&nbsp; (See the blog.)
<li>We love Team System.&nbsp; Despite its bugs, performance issues in a VPC and a tendency to be a bit counterintuitive in the UI, both Rich and I love Team System.&nbsp; Once the issues start getting solved and bugs fixed, this is going to be one very useful tool -- one that I won't want to be without!</li></ol>
